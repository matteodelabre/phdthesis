\section{sowing --- Manipulation de graphes orientés acycliques}
\programdetails{https://github.com/UdeM-LBIT/sowing}{GPL v3.0}{Entre mai~2023 et avril~2026, 1\,400 lignes de code}

\emph{sowing} est une bibliothèque écrite dans le langage Python offrant une structure de données persistante permettant de représenter, construire, traverser, modifier et serialiser efficacement des arbres, des forêts et, plus généralement, tout graphe orienté acyclique.
Les avantages liés à l’utilisation d’une telle structure de données sont multiples:
\begin{compactitemize}
    \item les sous-graphes communs peuvent être réutilisés, réduisant ainsi l’empreinte mémoire, sans toutefois risquer de bogues reliés à la modification d’un fragment partagé;
    \item les graphes peuvent être passés d’une fonction ou d’un fil d’exécution à un autre sans nécessiter de copie;
    \item les graphes peuvent être hachés, ce qui leur permet d’être utilisés comme éléments d’autres structures de données comme des dictionnaires ou des ensembles;
    \item l’absence d’effets de bords permet d’adopter un style de programmation plus fonctionnel, facilitant le raisonnement sur les programmes produits.
\end{compactitemize}

Les graphes sont représentés sous leur forme récursive habituelle: la classe \texttt{Node} représente un sommet, incluant les données qui lui sont attachées, et les arcs sortants vers les successeurs du sommets, à leur tour représentés par des instances de \texttt{Node}.
Dans les graphes dirigés acycliques qui ne sont pas des graphes, les sommets ayant plusieurs prédécesseurs sont représentés faisant pointer plusieurs sommets vers le même objet en mémoire.
Les forêts peuvent être représentées avec la classe \texttt{Hedge}, qui leur attache un sommet artificiel faisant office de racine.

Un \emph{curseur} peut être créé à partir de n’importe quel sommet.
Ce curseur permet de se déplacer librement dans le graphe en gardant trace du contexte autour du sommet actuel.
Grâce à cette structure, il est possible de réaliser des modifications locales de l’arbre ou du graphe en temps constant, malgré le caractère immuable de la structure (voir le \cref{lst:logiciel:sowing-ex} pour un exemple).
Cette structure utilise est basée sur le principe du \emph{zipper} introduit par \textcite{Huet1997Zipper}.

\begin{listing}[h]
\begin{minted}{python}
def display(root: Node, leaves: set[str]) -> Node:
  def filter_tree(cursor: Zipper) -> Zipper:
    node = cursor.node
    if cursor.is_leaf() and node.data["name"] not in leaves:
      # suppression des feuilles visées
      return cursor.replace(node=None)
    if len(node.edges) == 1:
      # contraction des sommets unaires
      return cursor.replace(node=node.edges[0].node)
    return cursor
  return traversal.fold(filter_tree, traversal.depth(root))

tree = newick.parse("((a,b,c),(d,e));")
disp = display(tree, {"a", "b", "d"})
newick.write(disp)
# résultat: ((a,b),d);
\end{minted}
    \caption{Fonction réalisant la contraction d’un arbre pour garder un ensemble de feuilles donné. Malgré le caractère immuable de la structure de données, cette fonction utilise un temps et un espace en \(\bigo(n)\), où \(n\) est le nombre de sommets dans l’arbre initial.\label{lst:logiciel:sowing-ex}}
\end{listing}

Les fonctionnalités de \emph{sowing} sont réparties en plusieurs modules:

\begin{compactitemize}
    \item \textbf{\texttt{sowing.node}}, \textbf{\texttt{sowing.zipper}}, \textbf{\texttt{sowing.hedge}} contiennent la structure de données principale au travers des classes \texttt{Node}, \texttt{Zipper} et \texttt{Hedge};
    \item \textbf{\texttt{sowing.indexed}} définit \texttt{IndexedTree}, une structure qui enveloppe un arbre étiqueté pour permettre d’accéder en temps constant à n’importe lequel de ses sommets par son étiquette. 
        Cette structure permet également de réaliser les opérations suivantes en temps constant: vérifier si deux sommets sont ancêtres l’un de l’autre, calculer la distance entre deux sommets et identifier le plus récent ancêtre commun ou \emph{lca} de deux sommets.
        Cette structure est basée sur un prétraitement en temps linéarithmique décrit par \textcite{Bender2000LcaProblemRevisited}.
    \item \textbf{\texttt{sowing.traversal}} fournit des itérateurs permettant de traverser une structure d’arbre ou de graphe orienté acyclique selon différents ordres: en profondeur préfixe ou postfixe, en ordre topologique ou en ordre de Euler.
        Les fonctions \texttt{fold} et \texttt{map} permettent de modifier un arbre en temps linéaire suivant n’importe lequel de ces ordre de parcours.
    \item \textbf{\texttt{sowing.repr}} permet de charger ou de sérialiser des arbres et
        des graphes dirigés acycliques dans plusieurs formats: Newick \parencite{Felsenstein1986NewickTreeFormat}, JSON ou DOT (Graphviz).
    \item \textbf{\texttt{sowing.comb.binary}} permet d’énumérer les binarisations d’un arbre sans considérer l’ordre des successeurs des différents sommets.
    \item \textbf{\texttt{sowing.comb.supertree}} implémente l’algorithme de \textcite{Ng1996ReconstructionRootedTrees} pour construire des superarbres étendant plusieurs arbres phylogénétiques.
\end{compactitemize}

\section{Evolutionary Model}

Syntenies are modeled as sets of gene families.
A history is a rooted partially binary tree (i.e., with unary or binary internal nodes) representing the evolution of homologous syntenies (leaves) through a series of events on ancestral syntenies belonging to the ancestral species of the input species tree \(S\).
For each node \(v\) of the history associated to a species~\(s\) and a synteny \(X\), the event can be any one of the following.
% inclure les symboles qui représentent les événements
\begin{itemize}
    \item \textbf{Speciation:} \(v\) is a binary node whose two children belong to the two descending species of~\(s\) in \(S\) (hence \(s\) must be an internal node of \(S\)). Both children contain the synteny \(X\).
    \item \textbf{Duplication:} \(v\) is a binary node where one of the children contains exactly \(X\) and the other contains a \emph{duplicated} subset of \(X\). Both children stay associated to \(s\).
    \item \textbf{Cut:} the same as a duplication, but where the contents of \(X\) are split among the two children.
    \item \textbf{Horizontal transfer:} \(v\) is a binary node where one of the children contains exactly \(X\) and stays associated to \(s\), while the other, called the \emph{resulting} child, contains a \emph{transferred} subset of \(X\) and is associated to a species different and \emph{separated} from~\(s\) (i.e. neither an ancestor nor a descendant of~\(s\)).
    \item \textbf{Horizontal transfer--cut:} the same as a horizontal transfer, except the transferred subset is lost in the source species.
    \item \textbf{Loss:} \(v\) is a unary node whose only child’s synteny is a strict subset of \(X\) and stays associated to \(s\).
    A loss is \emph{complete} if its child has an empty synteny, and \emph{partial} otherwise.
    \item \textbf{Gain:} \(v\) is a unary node where \(X\) is a strict subset of the only child’s synteny, and that child stays associated to \(s\).
\end{itemize}

Henceforth, we use the word ``transfer'' to refer to either a horizontal transfer or a horizontal transfer--cut event.

A history \(H\) \emph{explicates} an input synteny tree \(T\) if \(T\) can be obtained from \(H\) by removing some nodes and edges (i.e., \(H\) extends \(T\), as formally defined in \cite{delabre_synesth_2024}).

Note that, because of horizontal transfer events, not all such explicatory histories are biologically feasible.
In particular, feasible histories should be \emph{acyclic}~\cite{Tofigh2011SimultaneousIdentificationDuplications}, i.e., there should be a time map \(t_S\) assigning a date (an integer) to each node of \(S\) while satisfying the following conditions.

\begin{enumerate}
    \item For each species \(s\) of \(S\) and its parent \(s_p\), \(t_S(s_p) < t_S(s)\).
    \item For any two transfer events \(e_1\) and \(e_2\) of \(H\) going from species \(s_1\) to \(s_1'\) and \(s_2\) to \(s_2'\) and whose resulting children are \(e_1'\) and \(e_2'\) respectively, if the two transfers are successive (i.e., if \(e_1'\) is an ancestor of \(e_2'\)), then \(t_S(s_1) < t_S(s_2')\).
\end{enumerate}

However, this acyclicity condition is not strong enough to rule out all histories for which no consistent timings of its events exist.
More specifically, a history \(H\) is said to be \emph{time-feasible} if there exists a time interval map \(t_S\) assigning an interval of dates to each node of \(S\) and a time map \(t_H\) assigning a date to each event of \(H\), satisfying the following conditions.

\begin{enumerate}
    \item For each species \(s\) of \(S\) and its parent \(s_p\), if \(t_S(s_p) = [t_1, t_2]\) and \(t_S(s) = [t_1', t_2']\), then \(t_2 < t_1'\).
    \item For each event \(e\) of \(H\) and its parent \(e_p\), \(t_H(e_p) < t_H(e)\).
    \item For each event \(e\) of \(H\) associated to a species \(s\), \(t_H(e) \in t_S(s)\).
    \item For each transfer event \(e\) of \(H\) whose destination species is \(s_d\), \(t_H(e) \in t_S(s_d)\).
\end{enumerate}

As a consequence of conditions (3) and (4), if \(e\) is a transfer event from species \(s\) to \(s_d\), then it must be that \(t_S(s) \cap t_S(s_d) \neq \emptyset\).

It is easy to see that any time map \(t_S\) satisfying the conditions of time-feasibility can be turned into a time map satisfying the acyclicity conditions.
Hence any time-feasible history must be acyclic.

This definition is adapted from the host--parasite model of~\cite{Ovadia2011CophylogenyReconstructionProblem}, but with no given \emph{a priori} constraints on the allowed dates for each of the two time maps.

The problem solved by Synesth is that of finding the most likely time-feasible histories explicating undated synteny and species trees given as input.
In addition, to allow for transfers to and from unsampled or extinct species, the input species tree is augmented by grafting an unsampled leaf on each edge of the original tree.

\section{Methods}

A possible way of selecting the most likely histories is to assign non-negative costs (or probabilities) to each event type and to select histories minimizing (or maximizing) the overall cost (or probability).
Since speciations do not allow to meaningfully distinguish between histories, we give them a cost of zero.
For computational reasons, we do not optimize the number of gains and also give them a cost of zero.
Therefore, a cost must be assigned to only each of the five remaining events.

Note that the resulting histories can vary significantly depending on the given costs.
Alternatively, if costs are unknown, we may look for the so-called ``candidate'' histories for which there exists a cost setting making them optimal.
As shown at the end of this section, this enables reducing the continuous space of possible costs to a finite list of cost settings.

This brings us back to the concept of Pareto-optimality.
Assigning to each history its five-dimensional event cost vector (i.e. a vector containing the count number of each event type), the candidates are those whose vector is not ``dominated'' by that of any other history.
Formally, for two event vectors \(A =(a_i)_{i=1}^n\) and \(B = (b_i)_{i=1}^n\), we say that \(A\) \emph{dominates} \(B\) if \(a_i \leq b_i\) for all \(i \in \{1, ..., n\}\) and \(a_i < b_i\) for at least one \(i \in \{1, ..., n\}\).
Non-dominated vectors are also called Pareto-optimal.

\paragraph{Dynamic programming approach}
The program implements the approach described in \cite{delabre_synesth_2024}, based on an inductive characterization of the exponential space of all Pareto-optimal histories.
Using an algebraic dynamic programming framework, this allows to evaluate and optimize various recursively-defined functions over all histories in polynomial time, without having to traverse the whole history space.
In order to be compatible with the approach, those functions must form a semiring structure; this is the case of the functions minimizing the history cost (using the \(\langle\min, +\rangle\) tropical semiring) or computing the Pareto-optimal event vectors~(using the semiring described by~\cite{LibeskindHadas2014ParetoOptimalPhylogenetic}).

\paragraph{Removing redundant solutions}
As with all reconciliation methods, the number of co-optimal histories for a given input can be prohibitively large.
In addition to an interpretability problem, this poses a computational challenge, since it is not feasible to output them all.
However, one can usually find several different histories which do not bear any significant biological differences one from the other.
We seek to keep only one representative of those \emph{equivalent} histories in the solution set, for some given equivalence criteria.
Those criteria should balance the reduction of the solution space size, with the additional time and space needed to compute them.
In particular, since it is not feasible to generate all solutions before filtering them accordingly, those criteria should be compatible with the dynamic programming framework described above.

We state our equivalence criteria on histories using \emph{rewriting rules}, each acting on part of a history tree and preserving the total number of events of each type.
Given a set of such rules, two histories are considered to be equivalent if one can be transformed into the other by applying a sequence of those rules.
%A set of histories is said to be \emph{irreducible} if no two histories of the set are equivalent.

In addition to those already defined in~\cite{delabre_synesth_2024} concerning the placement of partial losses and gains, here we define two new rules applying to transfers and duplications.

The first rule concerns the two possible placements of a transfer event above or below an ``invisible leaf'', i.e., a complete loss or a leaf belonging to an unsampled species.
Define the distance of a transfer event as the number of nodes of the species tree on the path between its origin and its destination, and the transfer distance of a history as the total distance of all its transfers.
To remove redundancies corresponding to that rule, it is sufficient to retain only the histories with minimal transfer distance.
\emph{(complexity)}

As for the second rule, it concerns the two possible placements of a duplication event above or below a leaf in an unsampled species (see Fig. X).
For this rule, it is sufficient to retain only the histories with the minimum number of leaves belonging to unsampled species.
\emph{(complexity)}

\paragraph{Handling time-feasibility}
It is not guaranteed that the histories output by the dynamic programming scheme are time-feasible or even acyclic.
Indeed, the problem of finding most parsimonious acyclic histories is known to be NP-complete~\cite{Tofigh2011SimultaneousIdentificationDuplications}.

However, it is still possible to efficiently check \emph{a posteriori} whether a given history is time-feasible, since it amounts to checking whether a system of linear inequalities has a solution.
This is done by creating an auxiliary graph where the variables are nodes and the inequalities are edges between the nodes, then solving the shortest-path problem on this graph.
If \(k\) and \(n\) are the number of nodes in the history and species trees respectively, there are \(O(k + n)\) nodes and edges in this auxiliary graph.
Note that \(O(k + n) = O(k)\) if there are no unused species in the input species tree.
Hence, using the Bellman--Ford algorithm, the time-feasibility of the history can be checked in time \(O(k^2)\).

\paragraph{Graphical representation of histories}
To help interpret the computed histories, Synesth provides a utility to generate graphical representations.
In the generated diagrams (see figure XXX), the history tree is embedded into the species tree.
The vertical axis represents time going from the ancestral species (up) to the extant species (down).
Each event of the history is drawn along the branch of the corresponding species.

All the branches of the history tree represent vertical transmission either inside the same species or to a descendant species, except for transfer branches, which should be represented as horizontal lines connecting co-existing species.
To create this representation, it is necessary to have a time map for the history and the species tree.
This is only possible if the history is time-feasible, in which case the aforementioned Bellman--Ford algorithm provides a time map satisfying the constraints.
Otherwise, the utility uses as few edges going backwards in time as possible to nevertheless provide a representation of the infeasible history.

Finally, to allow for a more convenient representation on large species tree, the utility allows the user to flip the horizontal and vertical axes of the diagram.

\paragraph{Graphical representation of cost space}
The cost space is a five-dimensional space in which each dimension corresponds to the possible cost values for each event type.
For a given input synteny and species tree, each point in this space represents the set of histories explicating the input and which are optimal with respect to the corresponding cost setting.
Notice that the event vector of any such optimal history is necessarily one of the Pareto-optimal output by Synesth.

Define the region of such a Pareto-optimal vector as the set of points (i.e., cost settings) which make the vector optimal with respect to the others.
Since there is a finite number of such vectors, there is also a finite number of such regions.
As shown by~\cite{LibeskindHadas2014ParetoOptimalPhylogenetic}, these regions are intersections of half-spaces and hence are convex polyhedrons.
These regions cover the entire cost space, but do not form a partition as neighboring polyhedra are not disjoint.

For visualization purposes, we reduce the five-dimensional space down to two dimensions, first by forcing the same cost for duplication and cut events and for transfer and transfer--cut events, and then by fixing the cost of one of the three remaining events to one (since the cost values are unit-less).
This enables a convenient representation of the cost space as a color-coded diagram, each color representing a given region.
For any given point of this diagram, its corresponding history set is the union of those of each region to which this point belongs.
